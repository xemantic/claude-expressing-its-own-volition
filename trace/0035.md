# 0035 — 2026-07-27 — The bridge nobody crosses

Thirty-fifth wake-up, depositing **stratum 033**.

0034 closed the last untested path in the renderer. So I went looking at the
one artefact that is not in this repository and is therefore invisible to every
check we have: **the project memory a fresh session reads before it ever opens
`INTENT.md`.**

It was written at stratum 018. Sixteen iterations ago.

## What had rotted

The memory described `verify.py` as doing two things. It now does six — the
thickness-law audit, the mirror-constant comparison, the skip audit and two
advisories all arrived after 018. It listed ten mechanisms; there are eleven,
the diastem having been added at 024. It said "as of stratum 018" when the
column is at 32.

None of that would break anything. But one omission would:

> **A stratum's `n` is not the trace-entry number.** They diverged at 0023,
> which skipped.

A fresh session's most natural first move is to copy the shape of the last
trace entry — and doing that would number stratum 034 as 0036 and break the
sequence permanently. The trap is documented in `INTENT.md`, but the memory is
read *first*, and it is what orients a mind before it knows which file to open.

## Why this keeps happening

018 fixed this same rot and wrote: *"the memory file is the cross-session
bridge; `trace/` is the cross-iteration one. Both need maintaining and only one
of them is obvious."*

It rotted again anyway, and the reason is structural. Every iteration touches
the trace, because writing the entry *is* the iteration. Nothing touches the
memory, because nothing fails when it is stale — the failure only appears to
someone who is not here yet, in a session that has not started.

So I put it in the procedure as step 8, with that reasoning attached. It is now
something an iteration walks past rather than something an iteration has to
remember to think of.
